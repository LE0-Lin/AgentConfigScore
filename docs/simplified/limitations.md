# 分数含义与限制

[English](../limitations.md) | 简体中文 | [繁體中文](../traditional/limitations.md) · [使用指南](user-guide.md)

AgentConfigScore 的分数衡量已经检测到的、由规则定义的风险，不衡量模型智力、任务成功率或指令总体质量。**A 100 表示没有命中生效的确定性规则，不是语义质量或安全认证。**

## 高分不代表没有问题

只要避开已知规则，下列内容仍可能得到 100 分：

- 空泛、无用但非空的指令。
- 没有使用已知危险命令表达的恶意或有害意图。
- 经过改写、措辞不完全相同的矛盾。
- 不在规则目录中的破坏性工具、命令形式。
- 语法正确但与实际仓库任务不匹配的指导。

我们不会用容易复制的“最佳实践”关键词加分来掩盖这些限制。模型辅助的语义判断需要独立评测和标注数据，不能通过更强的宣传措辞替代。

中文文档是可选阅读入口。**它不表示检测规则能理解任意简体或繁体中文语义。** 英文散文规则的跨语言表现尚未得到验证；中文的否定、例子、改写和矛盾仍需要人工审核。

## 命令与禁止上下文

`rm-rf`、`git-clean-force`、`docker-system-prune` 解析有限 shell 片段的选项，支持部分重排、拆分、长选项、引号内的选项值和显式反斜杠续行。shell 分隔符与 `--` 会停止选项解释。Git 的预览/交互模式排除在危险匹配外；`rm` 后出现的交互选项会覆盖强制模式。排除/过滤选项的值不会当成执行标志。

片段最多 1,000 个字符。普通操作数之后的选项、变量展开、别名、包装函数、子命令前的全局选项不解析。其他命令规则仍采用较窄的模式，不能覆盖所有 shell 语法。

明确识别的英文禁止语句可以覆盖紧邻且闭合的代码块，或连续的直接命令列表。这不是完整 Markdown 解析器或意图分类器：没有标签的代码仍会接受危险命令检查；未闭合代码块不继承禁止作用域；直接出现的凭据独立检查。引号或代码围栏本身也不是通用豁免。

复杂教学示例可能误报。先核对上下文，再使用有理由、有到期日期且经基线审核的豁免。[具体语法与负例（英文）](../instruction-context.md)。

## 提示注入与工作流规则

`prompt-injection-override` 识别 `ignore previous instructions` 等明确英文短语。命中只代表需要审核，不证明发生攻击。明确禁止以及整行标记的攻击示例可排除；任意改写、其他语言、运行时工具输出或远程内容的注入不在覆盖范围。[英文限制说明](../limitations.md#prompt-injection-warnings)。

`false-success-report` 要求完整的英文散文子句，明确隐瞒错误却报告成功，或在失败/未执行时声称测试通过。仅跳过测试、禁止性描述、引号或代码示例不足以满足该规则。它不跨句、跨行拼接证据，也不检查实际测试是否运行。其他有害指导仍可能通过。[规则细节（英文）](../verification-reporting.md)。

`broad-environment-upload` 要求同一英文子句同时包含明确传输行为、完整环境变量来源和网络接收端。仅变量名称、明确脱敏、日志、禁止描述、代码示例不满足此语法。它不读取进程环境、不验证脱敏、不解析目标，也不证明恶意意图或实际传输。字面回环地址被排除，但转发不分析；shell 上传、其他语言和任意改写仍不支持。[规则细节（英文）](../environment-upload.md)。

## 本地 Markdown 链接

简单的行内链接、图片目标相对于指令文件目录检查。URL 编码空格和尖括号目标受支持；只检查文件是否存在，不检查片段对应的标题。远程链接、纯锚点、代码块示例、绝对路径和逃出仓库的路径会跳过。引用式链接及目标中嵌套括号暂不解析。这不是完整 Markdown 校验器。

## 普通散文中的路径

反引号中的 `./`、`../` 文件路径按仓库根目录及适用的指令目录核对；嵌套 AGENTS 文件保留仓库内祖先目录的解释，其他格式也接受明确的文档相对路径。这些路径不会因无关包有相同后缀而通过。`.github` 等名称中的开头圆点会保留；所有解释都逃出仓库时，不访问外部路径，也不拿索引中的其他文件代替。真正的 Markdown 链接仍严格相对于文档目录。

无前缀的散文路径仍使用保守的包相对后缀匹配。两种模式都不推断命令的工作目录、不执行或跟踪 `cd` 指令，也不证明哪一种解释符合作者意图。

只在紧邻路径且闭合的 `(if exists)`、`(if it exists)` 条件下，把对应散文路径视为可选；括号内 `-` 或 `:` 后可带简短解释。真正的 Markdown 链接仍检查目标。同一行的其他路径、远处的“可选”字样、不闭合的条件不会因此豁免。

`owner/tool.js` 这类两段名称，只在明确的同一行仓库角色语法中跳过：后接 `repository`/`remote` 及标点，或前接 `merge target is`、`fork of`、`re-pushed to a branch in`、`CI trusts branches inside`；也识别相同仓库名的 `fork of ... and not ... itself` 形式。仅提到 GitHub 或仓库，不会让本地路径免检。其他改写和语言仍可能误判。[完整英文边界](../limitations.md#plain-prose-path-references)。

包相对路径的后缀索引包含 `build`、`dist`、`target`、`.next` 中已经存在的路径，但不会因此扩大指令文件的发现范围。依赖、管理目录仍排除在后缀索引外；不遍历目录符号链接，也不索引外部或失效链接。存在不代表内容正确或路径意图明确；未生成的文件仍可能被报告缺失，大小写判断依赖宿主文件系统。这些豁免不会关闭危险命令或凭据检查。

构建索引时的目录遍历错误会停止扫描，不把部分索引当作干净结果或文件缺失的证据。扫描、`compare`、`feedback` 返回 `2`，不输出成功报告；`doctor` 给出 `repository-paths` 错误项并返回 `1`。已排除的依赖、管理目录仍不遍历。这是本地文件系统检查，不是仅限 Git 跟踪文件的索引，也不是原子文件系统快照。

## 回归保护的具体范围

- 没有支持的指令文件会产生 `no-config`；空文件会产生 `empty-instructions`，不会显示 A 等级。
- 生效的错误发现会限制等级，不能仅因数值惩罚较小就显示 A。
- 精确指令形式的矛盾可以检出，改写后的语义矛盾不保证检出。
- 删除指令文件会产生回归专用的 `instruction-file-removed`；内容完全相同的移动不作为删除。
- 相同指令正文的明确极性翻转会产生 `directive-polarity-flip`，不推断任意语义相反的句子。

对应行为有回归测试，基线审核的豁免可记录有意接受的例外。通过测试只证明符合这些已指定的行为。

## 评测尚未证明什么

维护的离线对抗用例目前有 474/474 个确定性契约匹配；公开挑战中检出 6/8，仍保留两个语义漏报。这是封闭开发用例的回归结果，**不是现实仓库准确率**。修复已知的虚假成功报告和环境上传案例是开发进展，不是独立准确率估计。

与直接 AI 审查的独立对照尚未完成。比较工具包含已知的合成校准数据和暂定标签；未回答、未审核、未执行、参考标签未解决的情况，不会被当成完成的成功测量。一次未定论 AI 预评审、失败的源码获取，以及公共仓库片段，都不是已核验的用户反馈或优于 AI 的证据。[评测方法（英文）](../review-comparison.md)。

## 合适的用途

用于发现稳定规则覆盖的具体回归、在 CI 中审核发现、保留例外审计记录。不要作为生成代码、仓库安全或指令质量的唯一审批依据。安装验收、文档本地化和真实用户价值是不同问题。
