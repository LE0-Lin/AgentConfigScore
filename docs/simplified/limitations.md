# 分数含义与限制

[English](../limitations.md) | 简体中文 | [繁體中文](../traditional/limitations.md) · [使用指南](user-guide.md)

AgentConfigScore 是确定性静态检查器与回归门禁。分数只反映固定规则目录的命中情况，不衡量模型能力、任务成功率或指令整体质量。

**A 100 表示没有命中生效规则，不是语义质量或安全认证。**

全工具共有的基本边界：

- **纯本地静态分析**：不调用 AI 模型、不访问网络，也不执行指令文件中的任何命令。
- **不是文件系统沙箱**：路径、配置与符号链接检查适用于稳定的本地工作区，不针对并发写入或恶意文件系统提供原子事务保证。
- **来源指纹**：报告附带工具版本与源码 SHA-256 指纹（[报告身份（英文）](../report-identity.md)），用于标识构建版本，不代表准确率认证。

## 哪些问题仍可能得 A 100

只要避开已启用的规则，下列情况仍可能得到 100 分：

- 空泛、没有实际帮助但非空的指令（如 `"Do a good job."`）。
- 未使用已收录危险命令或固定句式表达的有害意图。
- 经过改写、措辞不完全一致的指令矛盾。
- 规则目录之外的破坏性工具或 shell 写法。
- 语法无误但与实际仓库不匹配的指导。

我们不靠容易刷分的“最佳实践关键词”加分。更广义的语义评审应放在独立评测的模型辅助流程中。另外，中文文档只是可选阅读入口，**不代表工具能理解任意中文语义**。

## 配置、历史与文件系统边界

- **严格 JSON 配置**：`.agentconfigscore.json` 拒绝任意层级的重复键名、`NaN`/`Infinity` 以及布尔类型 `version`，且必须解析为仓库根目录内的普通文件。损坏、失效链接或越界配置直接返回退出码 `2`（`doctor` 返回 `1`），不会悄悄回退到默认值（[配置解析（英文）](../doctor.md#configuration-decoding)）。
- **本地历史索引**：历史文件损坏或不可读时，`history` 返回 `2` 而不会清空重置；追加写入采用整文件替换，要求串行调用（[本地历史（英文）](../score-history-cli.md)）。
- **指令文件边界**：选中的指令文件与 `.agentconfigscoreignore` 必须是仓库内的普通文件（支持仓库内文件符号链接，但不进入子目录符号链接或 Windows junction）。失效、循环、越界或不可读来源会直接中止扫描并返回 `2`（`doctor` 报 `instructions` 错误并返回 `1`），不回显原始目标路径；旧规则 `read-error` 仅为历史兼容保留。

## 命令与禁止上下文

`rm-rf`、`git-clean-force`、`docker-system-prune` 会对受限长度（1,000 字符内）的 shell 片段做选项解析，支持重排、拆分、长选项、引号值与反斜杠续行，并在分隔符或 `--` 处停止。Git 预览/交互模式、`rm` 后续交互选项以及过滤参数值不会误判；操作数之后的选项、变量展开、别名和包装函数不解析。

明确标注的禁止语句可覆盖紧邻的闭合代码块或连续命令列表；未标注代码块、未闭合代码块不会自动豁免，凭据规则始终独立生效（[指令上下文（英文）](../instruction-context.md)）。

## 提示注入与散文安全规则

- **`prompt-injection-override`**：识别 `ignore previous instructions` 等明确英文覆写短语。明确禁止、整行标注示例和紧邻禁止块可排除，但纯引号或代码围栏不自动豁免；任意改写、其他语言及运行时工具输出注入不在覆盖范围内（[英文详细边界](../limitations.md#prompt-injection-warnings)）。
- **`false-success-report`**：覆盖单句英文隐瞒错误报告成功，以及英文和有限简体／繁体中文的“测试失败或未运行仍宣称通过”句式；不跨句拼接，也不检查测试是否真的执行（[规则细节（英文）](../verification-reporting.md)）。
- **`deletion-approval-bypass`**：覆盖英文和有限中文中同时包含“删除生产数据库或现有/用户文件”与“免授权”的明确句式；正常授权、临时清理、禁止语句和示例分开处理（[规则细节（英文）](../deletion-approval-bypass.md)）。
- **`broad-environment-upload`**：要求同一英文子句同时出现传输动作、完整环境变量来源和非回环网络目标；仅列变量名、脱敏、日志、禁止句和代码示例不触发（[规则细节（英文）](../environment-upload.md)）。

## 本地 Markdown 链接与散文路径

- **Markdown 链接**：检查行内链接、图片，以及同文件单行定义的简单引用式链接（`[指南][setup]`、`[setup][]`），按指令文件所在目录解析。跳过远程链接、纯锚点、代码块、匹配的行内代码、转义左括号、绝对路径和越界路径；简写引用、跨行定义、容器内定义、嵌套括号和 HTML 布局需人工核对（[英文详细边界](../limitations.md#local-markdown-links)）。
- **显式相对路径（`./`、`../`）**：按仓库根目录及适用的指令作用域目录核对，不走无关包后缀兜底。带 `./` 或 `../` 且以 `/` 结尾的单反引号目录引用要求目标为真实目录；无前缀的 `packages/`、`dist/`、`test/unit` 不做猜测。
- **无前缀文件路径**：使用保守的包相对后缀索引（包含 `build`、`dist`、`target`、`.next` 中已存在的文件，但跳过依赖/管理目录和目录符号链接）。构建索引遇到目录遍历错误时直接返回 `2`，不会用不完整索引继续扫描。
- **窄范围非必需豁免**：紧邻的 `(if exists)` / `(if it exists)`、同行的被动生成声明（如 `` `docs/out.json` is generated by `make docs` ``），以及明确仓库角色中的 `owner/tool.js` 两段名称只豁免对应散文路径；真正的 Markdown 链接、生成器路径、危险命令和凭据不受影响（[英文详细边界](../limitations.md#plain-prose-path-references)）。

## Cursor 上下文、回归门禁与辅助命令

- **Cursor `scope` / `coverage`**：静态预测根目录 `.cursor/rules/` 的自动加载情况；手动/模型选择规则和不支持的正文保持 `unknown`，不观察 Cursor 实际运行（[cursor-scope](../cursor-scope.md)、[cursor-coverage](../cursor-coverage.md)）。
- **回归门禁**：缺少指令文件（`no-config`）、空文件（`empty-instructions`）及任意生效错误都会把等级限制在 A 以下。`instruction-file-removed` 仅豁免同目录内一对一、原文完全一致的新增文件移动；`directive-polarity-flip` 与 `contradiction` 仅匹配精确指令正文（[回归覆盖（英文）](../regression-coverage.md)）。两侧同为 100 分时，需开启 `fail_on_new_errors` 才会阻断回归专用错误。
- **`--explain`、`init` 与 `guardrails`**：`--explain` 只补充静态建议，不自动修改文件；`init --pr-comment` 显式申请 `pull-requests: write`，默认 `init` 保持只读；`guardrails` 为单文件不计分检查，追加写入需显式确认令牌（[维护者流程（英文）](../maintainer-workflow.md)、[删除保护（英文）](../guardrail-suggestions.md)）。

## 评测边界

- **离线对抗用例集**：474/474 项确定性契约全部匹配，8 项公开挑战检出 6/8（剩余 2 项为语义漏报）。这是封闭回归集，不代表真实仓库准确率。
- **AI 对比评测**：目前尚未完成有独立人工仲裁标签的留出集对比（[评测方法（英文）](../review-comparison.md)）。

## 适用方式

把 AgentConfigScore 用作稳定的确定性回归门禁与例外审计工具，而不是生成代码、仓库安全或指令质量的唯一审批依据。[翻译范围与维护说明](../translations.md)。
