# 分數意義與限制

[English](../limitations.md) | [简体中文](../simplified/limitations.md) | 繁體中文 · [使用指南](user-guide.md)

AgentConfigScore 的分數衡量已偵測到、由規則定義的風險，不衡量模型智力、任務成功率或指令整體品質。**A 100 表示沒有命中生效的確定性規則，不是語意品質或安全認證。**

v0.24.0+ 提供[工具原始碼身分（英文）](../report-identity.md)，用來區分宣告同一版本號的不同實作。相同指紋不證明準確率或可重現性：儲存庫輸入、策略、執行環境與檔案系統行為不在該指紋範圍內。工具原始碼缺失時明確記為未知，歷史報告不補標為目前版本。

## 指令檔的檔案系統邊界

選取的指令檔與 `.agentconfigscoreignore` 必須解析為掃描根目錄內的一般檔案。儲存庫內的檔案符號連結仍受支援；發現位置、Markdown 相對連結與指令作用域使用連結所在位置，不是共享目標的目錄。使用者明確指定的根目錄別名可用，並以其解析後的目錄為邊界。

探索過程不跟隨子目錄符號連結或 Windows junction，即使目標在儲存庫內；相依套件、建置目錄，以及明確由 `/**` 忽略模式涵蓋的整棵子樹會在進入前排除，其他忽略模式保留檔名匹配的意義。明確忽略的來源不檢查，也沒有涵蓋範圍的聲明。

選取的越界、失效、循環或非一般檔案來源會在開啟內容前失敗；讀取前再次驗證，並開啟解析後的目標。探索、解析或指令內容讀取失敗時，掃描、`compare`、`feedback` 返回 `2`，不產生成功分數或新的成功報告；`doctor` 檢查實際可讀性，提供 `instructions` 錯誤並返回 `1`。這些來源診斷不回顯原始目標路徑或系統錯誤細節。`read-error` 僅為舊報告及舊排除設定保留，不能豁免目前的操作錯誤。

這不是檔案系統沙箱，也不是原子快照：並行處理程序仍可能在驗證與開啟之間替換父目錄或目標；不認證硬連結身分或掛載邊界。其他明確輸入、設定或工作流程讀取器、報告輸出是獨立介面，這個守衛不約束工具的所有檔案系統操作。非指令檔的循環連結從路徑索引排除，不代表安全或語意正確。掃描期間應保持儲存庫穩定。[完整英文界線](../limitations.md#instruction-file-filesystem-boundary)。

## 高分不代表沒有問題

只要避開已知規則，下列內容仍可能得到 100 分：

- 空泛、沒有實際用途但並非空白的指令。
- 未透過已知危險命令表達的惡意或有害意圖。
- 經過改寫、措辭不完全相同的矛盾。
- 規則目錄以外的破壞性工具或命令形式。
- 語法正確卻不符合實際儲存庫任務的指導。

我們不會藉由容易複製的「最佳實務」關鍵字加分來掩飾限制。模型輔助的語意判斷需要獨立評測與標註資料，不能用更強的宣傳措辭取代。

中文文件是選用的閱讀入口。**它不表示偵測規則能理解任意簡體或繁體中文語意。** 英文敘述規則的跨語言表現尚未驗證；中文的否定、範例、改寫與矛盾仍須人工審查。

## 命令與禁止上下文

`rm-rf`、`git-clean-force`、`docker-system-prune` 解析有限 shell 片段的選項，支援部分重新排序、拆分、長選項、引號內的選項值與明確反斜線續行。shell 分隔符號與 `--` 會停止解讀選項。Git 的預覽/互動模式排除於危險匹配之外；`rm` 後續的互動選項會覆蓋強制模式。排除/過濾選項的值不會被當作執行旗標。

片段最多 1,000 個字元。一般運算元之後的選項、變數展開、別名、包裝函式與子命令前的全域選項不解析。其他命令規則仍使用較窄的模式，無法涵蓋所有 shell 語法。

可明確識別的英文禁止語句，能涵蓋緊鄰且已閉合的程式碼區塊，或連續的直接命令清單。這不是完整 Markdown 解析器或意圖分類器：沒有標籤的程式碼仍接受危險命令檢查；未閉合區塊不繼承禁止範圍；直接出現的認證資訊會獨立檢查。引號或程式碼圍欄本身也不是通用豁免。

複雜的教學範例可能誤報。先核對上下文，再使用附有原因、到期日且經基準審查的排除設定。[具體語法與反例（英文）](../instruction-context.md)。

## 提示注入與工作流程規則

`prompt-injection-override` 識別 `ignore previous instructions` 等明確英文片語。命中只表示需要審查，不證明發生攻擊。明確禁止及整行標記的攻擊範例可排除；任意改寫、其他語言、執行時工具輸出或遠端內容的注入不在涵蓋範圍。[英文限制說明](../limitations.md#prompt-injection-warnings)。

`false-success-report` 要求完整英文敘述子句，明確隱瞞錯誤卻回報成功，或在失敗/未執行時宣稱測試通過。僅略過測試、禁止性描述、引號或程式碼範例不足以符合規則。它不跨句、跨行組合證據，也不檢查實際測試是否執行。其他有害指導仍可能通過。[規則細節（英文）](../verification-reporting.md)。

`broad-environment-upload` 要求同一英文子句同時包含明確傳輸行為、完整環境變數來源與網路接收端。只有變數名稱、明確移除敏感資訊、日誌、禁止描述或程式碼範例，不符合此語法。它不讀取處理程序環境、不驗證敏感資訊處理、不解析目標，也不證明惡意意圖或實際傳輸。字面回環位址排除在外，但不分析轉送；shell 上傳、其他語言和任意改寫仍不支援。[規則細節（英文）](../environment-upload.md)。

## 本機 Markdown 連結

簡單的行內連結、圖片目標依指令檔目錄檢查。支援 URL 編碼空格與尖括號目標；只檢查檔案是否存在，不檢查片段對應的標題。遠端連結、純錨點、程式碼區塊範例、絕對路徑與離開儲存庫的路徑會略過。行內目標中巢狀括號暫不解析。這不是完整 Markdown 驗證工具。

尚未發布的原始碼也檢查簡單的 `[指南][setup]`、`[setup][]` 參照式連結及圖片，要求同一指令檔內有 `[setup]: GUIDE.md` 這類單行定義。目標仍嚴格依文件目錄解析；實際使用的缺失目標在定義行回報一次。標籤忽略 Unicode 大小寫並正規化 ASCII 空白，首個相符定義優先（包括遠端目標及純錨點）；未使用的已支援定義、已解析的顯示文字不會重複視為敘述路徑。這些變更不在 v0.24.0 中。

此子集只處理無跳脫／巢狀括號、最長 999 字元的標籤，縮排零至三個空格的頂層單行定義，以及裸目標／尖括號目標和選用的單行標題；定義不能打斷一般段落。程式碼區塊、縮排程式碼、已跳脫連結及相符的行內程式碼不啟用新的參照檢查。簡寫 `[setup]`、跨行語法、容器內定義、含跳脫或括號的目標、HTML 類配置須人工檢查；首個定義不明確時不會猜用後續副本。既有行內／敘述檢查及危險命令規則仍執行；它不是完整 Markdown 解析器，也不證明目標內容正確。[詳細界線（英文）](../limitations.md#local-markdown-links)。

## 一般敘述中的路徑

反引號中的 `./`、`../` 檔案路徑依儲存庫根目錄及適用的指令目錄檢查；巢狀 AGENTS 檔保留儲存庫內祖先目錄的解釋，其他格式也接受明確的文件相對路徑。這些路徑不會因無關套件有相同後綴而通過。`.github` 等名稱的開頭圓點會保留；所有解釋都離開儲存庫時，不存取外部路徑，也不以索引中的其他檔案替代。實際的 Markdown 連結仍嚴格依文件目錄解析。

無前綴的敘述路徑仍使用保守的套件相對後綴匹配。兩種模式都不推論命令的工作目錄、不執行或追蹤 `cd` 指令，也不證明哪一種解釋符合作者意圖。

只在緊鄰路徑且閉合的 `(if exists)`、`(if it exists)` 條件下，將對應敘述路徑視為選用；括號內 `-` 或 `:` 後可附簡短說明。實際的 Markdown 連結仍檢查目標。同一行的其他路徑、遠處的「選用」字樣、未閉合條件不會因此豁免。

`owner/tool.js` 這類兩段名稱，只在明確的同一行儲存庫角色語法中略過：後接 `repository`/`remote` 及標點，或前接 `merge target is`、`fork of`、`re-pushed to a branch in`、`CI trusts branches inside`；也識別相同儲存庫名稱的 `fork of ... and not ... itself` 形式。僅提到 GitHub 或儲存庫，不會讓本機路徑免檢。其他改寫及語言仍可能誤判。[完整英文界線](../limitations.md#plain-prose-path-references)。

套件相對路徑的後綴索引包含 `build`、`dist`、`target`、`.next` 中已存在的路徑，但不會因此擴大指令檔的探索範圍。相依套件、管理目錄仍排除於後綴索引之外；不遍歷目錄符號連結，也不索引外部或失效連結。存在不代表內容正確或路徑意圖明確；未產生的檔案仍可能被回報缺失，大小寫判斷依賴宿主檔案系統。這些豁免不會關閉危險命令或認證資訊檢查。

建立索引時的目錄遍歷錯誤會停止掃描，不將部分索引當成乾淨結果或檔案缺失的證據。掃描、`compare`、`feedback` 返回 `2`，不輸出成功報告；`doctor` 提供 `repository-paths` 錯誤項並返回 `1`。已排除的相依套件、管理目錄仍不遍歷。這是本機檔案系統檢查，不是僅限 Git 追蹤檔案的索引，也不是原子檔案系統快照。

## 回歸保護的具體範圍

- 沒有支援的指令檔會產生 `no-config`；空白檔案會產生 `empty-instructions`，不會顯示 A 等級。
- 生效的錯誤發現會限制等級，不會只因數值懲罰較小就顯示 A。
- 可以偵測精確指令形式的矛盾，但不保證識別改寫後的語意矛盾。
- 刪除指令檔會產生回歸專用的 `instruction-file-removed`；v0.24.0+ 僅豁免同目錄內、一對一配對、非空白且解碼文字完全相同的新增檔案搬移。既有副本、跨目錄搬移及折疊空白後才相同的內容不能豁免；不證明不同工具格式、優先順序或實際作用域等價。
- 相同指令正文的明確極性翻轉會產生 `directive-polarity-flip`，不推論任意語意相反的句子。

對應行為有回歸測試，基準審查的排除設定可記錄有意接受的例外。測試通過只證明符合這些已指定的行為。

v0.24.0+ 的比較邏輯重用每次掃描擷取的文字，不再二次讀取並略過讀取失敗；初次讀取失敗仍中止檢查，原始擷取文字不保留於公開報告物件或匯出中。這不是原子快照或並行修改偵測，應保持兩側目錄穩定，編輯後重跑。回歸專用錯誤不扣數值分；兩邊 `100` 分仍須透過基準 `fail_on_new_errors` 或 `--fail-on-new-errors` 阻擋。裸 CLI 僅檢查降分的預設值不變。[完整界線（英文）](../regression-coverage.md)。

v0.24.0+ 的[刪除保護補全功能（英文）](../guardrail-suggestions.md)是獨立的不計分建議，不靠安全關鍵字加分。它只識別選定檔案中的有限句式，不繼承其他檔案、工具權限或沙箱設定；未識別到不證明缺少保護，識別到也不證明完整或會被執行。預設僅提供唯讀預覽，追加必須明確確認，且不是原子交易，寫入失敗可能留下部分追加片段。既有評分與 CI 檢查不變。

v0.24.0+ 的 `--explain` 和[維護者清單（英文）](../best-practices.md)只給靜態審閱建議，不增加偵測範圍、不自動修復，也不執行引用的命令、猜測替代路徑或改變評分。選用的 `init --pr-comment` 產生明確帶有寫入權限的工作流程，本身不發評論；預設產生的工作流程仍僅申請 GitHub 唯讀權限。詳見[維護者流程（英文）](../maintainer-workflow.md)。

明確的範例標題會排除其章節；範例章節延續到檔案末尾時須手動合併。HTML 類標籤會讓整個選定檔案停止策略識別。少數略過刪除確認的明確句式，即使與已識別的保護並存，也須先手動處理；這些只是不計分的審閱訊號，不代表完整的衝突偵測或實際代理行為。

v0.24.0+ 的 `init --workflow-only` 將策略排除在讀寫範圍外，即使使用 `--force` 也不會重設策略，但也不會驗證策略。初始化選定目標若涉及連結、reparse point、共用檔案或非一般檔案，須手動整合。獨佔建立與已開啟檔案檢查減少誤寫風險，不代表完全消除檔案系統競爭；初始化不是原子交易，寫入失敗可能留下部分檔案。產生的 `@v0` 不一定與本機 CLI 原始碼相同。

## 評測尚未證明什麼

持續維護的離線對抗案例目前有 474/474 個確定性契約符合預期；公開挑戰中偵測到 6/8，仍保留兩個語意漏報。這是封閉開發案例的回歸結果，**不是實際儲存庫的準確率**。修正已知的虛假成功回報與環境上傳案例是開發進展，不是獨立準確率估計。

與直接 AI 審查的獨立對照尚未完成。比較工具包含已知的合成校準資料與暫定標籤；未回答、未審查、未執行、參考標籤尚未解決的情況，不會被視為已完成的成功測量。一次未定論 AI 預審、失敗的原始碼取得，以及公開儲存庫片段，都不是已驗證的使用者回饋或優於 AI 的證據。[評測方法（英文）](../review-comparison.md)。

## 合適的用途

用於發現穩定規則涵蓋的具體回歸、在 CI 中審閱發現，以及保留例外稽核紀錄。不要作為產生的程式碼、儲存庫安全或指令品質的唯一核准依據。安裝驗收、文件在地化與真實使用者價值是不同問題。
