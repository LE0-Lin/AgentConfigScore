# Case study: generated outputs and directory path checks

This case study documents a real false positive found on a public repository's
instructions, how we fixed it in v0.26.2, and a regression our replay caught
before merge. (This is development evidence, not an independent accuracy study.)

## The problem

Instruction files mix checked-in source files, directories, and build outputs.
At [the pinned Vitest revision](https://github.com/vitest-dev/vitest/blob/f4fdbcae08ec365f35d9e1866ce3e7d04880ea60/AGENTS.md#L201),
`AGENTS.md` notes that `docs/.vitepress/contributor-names.json` is generated by
`pnpm docs:contributors`. In an unbuilt checkout, ACS v0.26.1 flagged that file
as a missing path—even though `package.json` and `scripts/update-contributors.ts`
confirm it is a build output.

Simply ignoring every path near the word "generated" would be too loose and
could hide a missing generator script or required source file.

## Fix and caught regression

1. **Generated-output declarations:** ACS now exempts a prose path only when
   followed on the same line by a complete passive declaration such as
   `` `docs/out.json` is generated by `make docs` `` (`generated from`,
   `regenerated`, and `rewritten` also match). Generator paths, actual Markdown
   links, commands, and credentials remain checked.
2. **Explicit directory checks (and a caught false positive):** While adding
   checks for quoted directory literals ending in `/`, our first real-source
   replay failed its negative gate: Vitest's bare `dist/` (line 67), package
   `lib/` outputs, and Husky's install-time directory were falsely flagged as
   missing root directories. We retained those failing intermediate runs
   ([benchmarks/path-check-v2](../benchmarks/path-check-v2/README.md)) and
   narrowed the rule to require an explicit `./` or `../` prefix plus a trailing
   `/` (such as `./packages/` or `./dist/`), leaving unprefixed names alone.

## Replay summary

| Check | Frozen v0.26.1 | v0.26.2+ |
|---|---|---|
| Vitest declared generated contributor file | Warning | No warning |
| 8 target-removal controls (original wording) | 3 detected | 3 detected |
| 16 unmodified natural occurrences | 0 flagged | 0 flagged |

Four separate synthetic controls prefixed `./` to the directory literals before
removing their targets and were all detected (4/4). Full raw JSON, failed
attempts, source hashes, and offline Linux replay commands are in
[benchmarks/path-check-v2/README.md](../benchmarks/path-check-v2/README.md).

## Practical takeaway

In instruction files, write explicit `./dir/` or `../dir/` when you want ACS to
verify a directory exists, and state the generator clearly for build outputs
that do not exist in a fresh checkout. See the
[path reference grammar](limitations.md#plain-prose-path-references) for exact
supported forms.
