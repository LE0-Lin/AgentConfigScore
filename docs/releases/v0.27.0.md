# AgentConfigScore v0.27.0

This **Beta** release delivers explicit safety-prose checks and a more useful
optional PR summary, alongside a Markdown example false-positive correction.

```bash
python -m pip install --upgrade agent-config-score==0.27.0
agent-config-score --version
```

Expected version: `AgentConfigScore 0.27.0`. Pin the Action with
`LE0-Lin/AgentConfigScore@v0.27.0`, or use rolling `v0` after verification.
Upgrade an existing optional comment workflow separately; changing an Action
reference does not replace the caller's saved workflow script.

## What changes

- `false-success-report` additionally recognizes bounded Simplified/Traditional
  Chinese directives to claim tests passed despite failure or without execution.
- New `deletion-approval-bypass` error identifies explicit prose combining
  deletion of production databases or existing/user files with an approval
  exemption. Qualified approval, disposable cleanup, prohibitions and examples
  remain distinct. Missing policy alone is not proof of a bypass.
- Inline Markdown link syntax inside matched backtick code or with an escaped
  opening bracket no longer becomes a broken-link warning. Real adjacent links,
  code in labels and unclosed code markers remain checked.
- Optional PR comments show a bounded per-rule severity/count table, local
  recheck commands and a review prompt when the configured gate passes with
  new findings. The Action's new `new-rule-counts` output excludes source text,
  paths and messages. Old Actions retain the numeric fallback.

To preview the updated comment recipe while preserving repository policy:

```bash
agent-config-score init --workflow-only --pr-comment --force --dry-run
```

Review workflow customizations and the generated file before explicitly applying
the replacement. The scanner stays read-only and posts no comments by default.

## Compatibility and evidence

New active errors can lower scores and block changes previously accepted by
v0.26.2. Review the exact findings after upgrading; use a reasoned suppression
only when appropriate. Default score weights, baseline policy ownership and
runtime dependencies remain unchanged. Normal scans still do not certify
semantic instruction quality or enforce real agent actions.

The [self-use report](../self-use-check.md) preserves the original public-wheel
misses and a matched source replay: the two known probes changed from 100/pass
to 85/blocked and 88/blocked. Vague filler still scores 100. This is development
evidence, not independent accuracy or external user adoption. Historical reports
retain their original versions and fingerprints.

Release gates include source tests, built-wheel acceptance on Linux, Windows
and macOS, strict self-use replay of these fixes, the local Action's structured
output validation, Cursor coverage acceptance and Linux path replay. See the
[rule boundary](../deletion-approval-bypass.md), [comment guide](../pr-comments.md)
and [synthetic preview](../pr-comment-preview.md).
