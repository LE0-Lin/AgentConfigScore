# AgentConfigScore v0.26.0

This **Beta** release completes the optional Cursor coverage path from repository
setup to a CI decision, readable review summary and retained evidence. The core
product remains a local deterministic linter and baseline-governed regression gate.

## Install and adopt

```bash
python -m pip install --upgrade "agent-config-score==0.26.0"
agent-config-score --version
agent-config-score init --coverage-under src --dry-run
agent-config-score init --coverage-under src
```

Expected version is `AgentConfigScore 0.26.0`. Review and commit generated files.
For an existing installation, preview a workflow-only update first:

```bash
agent-config-score init --workflow-only --coverage-under src --force --dry-run
agent-config-score init --workflow-only --coverage-under src --force
```

Workflow-only mode preserves policy bytes. `--force` replaces the selected
workflow, including local customizations. Review the dry run before applying it.
Repeat `--coverage-under` for multiple directory prefixes. Normal initialization
without this option retains the ordinary score-only workflow.

## Review and recheck

```bash
agent-config-score scope coverage --base-ref origin/main --under src --fail-on-lost-directives --fail-on-unknown --markdown coverage-review.md --json
```

`--markdown` writes file/line evidence, gate reasons, unknown sources, exclusions
and review guidance. It preserves JSON output and exit behavior, including a
completed review failure with exit `1`. A report-write failure uses exit `2`
without successful JSON. Choose report paths outside instruction/policy files.
Report writes are not atomic multi-file transactions.

The generated CI workflow runs the normal baseline-governed gate and adds
strict coverage review for the selected prefixes. It uses read-only GitHub
permissions, publishes a job summary and retains completed Markdown/JSON reports
for seven days, including on review failure. Operational failures are labelled
unavailable, with diagnostics in the failed step log.

The Action's optional `coverage-under` input accepts newline-separated prefixes.
New `coverage-exit-code`, file/loss/unknown counts and report-path outputs let
callers retain their own evidence. Defaults preserve existing integrations.
Pin to `LE0-Lin/AgentConfigScore@v0.26.0` or a verified commit. The generated
workflow checks for coverage support, so pinning an older Action cannot silently
skip the requested check. The separate opt-in comment setup can be combined
with coverage; the comment's run link leads to the complete review summary.

## Acceptance and scope

Release publication waits for the source suite, installed-wheel acceptance on
Linux/Windows/macOS, and the real composite Action on seven disposable Git
fixtures. These cover narrowing, repair, rename, unknown loading, unchanged
inputs, empty selection and unreadable source. Tests check the actual Action
outcome, failure outputs, reports and temporary-worktree cleanup.

These are development acceptance cases. No native Cursor capture or independent
accuracy estimate is supplied. Scope analysis predicts the documented bounded
profile, with explicit uncertainty. Prefixes and strict coverage flags remain
caller-owned, separate from normal baseline score policy. Review trusted workflow
and tool revisions independently. See the [design and shipped boundary](https://github.com/LE0-Lin/AgentConfigScore/blob/v0.26.0/docs/architecture.md)
and [coverage guide](https://github.com/LE0-Lin/AgentConfigScore/blob/v0.26.0/docs/cursor-coverage.md).
