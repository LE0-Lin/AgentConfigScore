# AgentConfigScore v0.25.0

This **Beta** release packages opt-in Cursor attachment analysis and per-file
coverage review, together with stricter configuration and local-history handling.
The normal linter and baseline-governed score gate retain their existing policy
defaults. Cursor commands provide bounded static predictions with explicit unknowns.

## Install and verify

```bash
python -m pip install --upgrade "agent-config-score==0.25.0"
agent-config-score --version
agent-config-score scope coverage --help
agent-config-score doctor
```

Expected version is `AgentConfigScore 0.25.0`. Python 3.10+ is required. Git is
needed for comparisons against a local ref. Both console aliases and
`python -m agent_config_score` are available with zero runtime dependencies.

## Cursor attachment and coverage review

- `scope` predicts root `.cursor/rules/` automatic attachment for declared files.
  Its bounded metadata/glob grammar retains manual/model-selected and unsupported
  inputs as unknown. It keeps original metadata and directive line evidence.
- `scope compare` and `scope diff` compare the same declared context across two
  trees or a local Git baseline. Renames, another active copy and remaining
  multi-file triggers can preserve an exact recognized directive.
- `scope coverage` inventories filtered regular files in both trees and checks
  each independently. It can identify an API-only loss even when a task that
  also includes a matching frontend file would retain attachment. Sources are
  captured once per side and reused across file contexts.

```bash
agent-config-score scope coverage --base-ref origin/main --under src --fail-on-lost-directives --fail-on-unknown --json
```

The local baseline ref must exist. No ref is fetched. Prefixes and review flags
belong to the caller. Completed advisory analysis returns `0`; opted-in review
gates return `1`; invalid inputs, read failures and resource limits return `2`
without partial success JSON. Empty file selections fail. Files with zero
recognized baseline protection are counted explicitly.

These commands are unscored and separate from the normal Action's score-policy
schema. The reusable Action still runs its normal comparison. Invoke `scope`
explicitly in a caller workflow to add this optional check. The
[coverage guide](https://github.com/LE0-Lin/AgentConfigScore/blob/v0.25.0/docs/cursor-coverage.md)
describes inventory exclusions, bounds and the complete installed replay.

## Compatibility changes

- Configuration rejects duplicate decoded member names, non-standard numeric
  constants and Boolean format versions. Both comparison trees must validate.
  Review repeated fields deliberately instead of relying on last-value wins.
- Configuration sources must resolve to a regular file inside the selected
  repository. Dangling, external, cyclic and unreadable sources fail. Internal
  file aliases remain supported. Keep shared policy targets tracked inside each
  Git tree and repair invalid links explicitly.
- Malformed, unreadable, linked or otherwise invalid local history fails with
  exit `2`. The append helper preserves damaged input and uses a complete-file
  replacement. Back up and repair the index before retrying. Partial legacy
  snapshots remain readable. Callers must serialize writers.
- Explicit guardrail review selects its file without whole-tree instruction
  discovery. Normal scans still require whole-tree source preflight.
- Simple full/collapsed Markdown reference links now contribute path findings
  at the definition line. Existing rule IDs and penalties are retained; these
  corrections can change findings and scores.

Review [configuration migration](https://github.com/LE0-Lin/AgentConfigScore/blob/v0.25.0/docs/doctor.md#configuration-file-boundary)
and [history recovery](https://github.com/LE0-Lin/AgentConfigScore/blob/v0.25.0/docs/score-history-cli.md#invalid-history-and-recovery)
before upgrading. No automatic repair or hostile-filesystem transaction is provided.

## CI and reproducible examples

Pin CI to `LE0-Lin/AgentConfigScore@v0.25.0` or the verified release commit.
Rolling `@v0` follows releases. Package installation does not update an existing
workflow's pinned Action revision. Generated workflows continue to use `@v0`.

The release workflow requires the full source suite and acceptance of the same
built wheel on Linux, Windows and macOS before publication. Acceptance includes
five synthetic coverage cases, a joint-context control, unchanged standalone
scores, source identities and retained JSON artifacts. After installing the
package, replay the repository fixtures from a checkout with:

```bash
python scripts/run_cursor_coverage_demo.py --output cursor-coverage-demo.json
```

The repository gallery retains its explicitly labelled v0.24.0 recordings.
Historical releases and frozen research artifacts retain their original identities.

## Evidence limits

No native Cursor attachment capture is supplied. `observed_agent_context` remains
false. Static predictions, synthetic tests and installation acceptance establish
specified tool behavior, without establishing native loading fidelity, agent
compliance, independent accuracy or adoption. The existing AI pilot remains
unscored. A 100 score still means no active scored rule matched.

See the [model boundaries](https://github.com/LE0-Lin/AgentConfigScore/blob/v0.25.0/docs/limitations.md)
and [changelog](https://github.com/LE0-Lin/AgentConfigScore/blob/v0.25.0/CHANGELOG.md).
