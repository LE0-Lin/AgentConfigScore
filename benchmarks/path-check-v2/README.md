# Path checks: bounded fixes and reproducible evidence

This is **development evidence**, separate from external user feedback or
independent accuracy. The changed runtime is an unreleased source build. The
published v0.26.1 reports and its 474-case benchmark remain unchanged.

## Actual problems addressed

Vitest's pinned `AGENTS.md:201` explicitly says that
`docs/.vitepress/contributor-names.json` is generated by `pnpm docs:contributors`.
The [retained producer context](../path-audit-v1/posthoc-context.json) links that
command to `scripts/update-contributors.ts`, whose write target matches the
declared file. The original published scanner nevertheless warned about its
absence from the unbuilt Git checkout.

The fix recognizes a complete, immediate generated-output declaration. It
still checks the generator's own path, actual Markdown links, dangerous commands
and credential shapes. It trusts the declared output role, not its truthfulness;
it does not build the project or interpret arbitrary prose.

The earlier audit also exposed five misses when existing directory targets were
independently removed from verified path projections. Four use a quoted literal
with a trailing slash. Those now require an actual directory at a concrete
repository/scope base. `test/unit`, which has no trailing slash, remains a
documented heuristic boundary. The [full grammar and scope](../../docs/limitations.md#plain-prose-path-references)
includes package ambiguity, aliases, examples and filesystem limits.

## Replay, retain and inspect

The runner preserves the original source text, Git identities, old findings and
unfavorable controls. It compares current installed-source observations with
the frozen v0.26.1 results, without rewriting the original audit.

On Linux with a case-sensitive filesystem, from this checkout:

```bash
python -m pip install .
python scripts/run_path_regression_check.py --python /absolute/path/to/python \
  --output path-regression.json --markdown path-regression.md
```

Both outputs must be new. The current installed build is identified by a complete
source fingerprint, because the unchanged version string does not distinguish
unreleased code from PyPI v0.26.1. Git-verified path names are materialized as
empty regular files, plus exact selected instruction bytes; this is not a full
checkout, native discovery or evidence about upstream program behavior. Nothing
from the upstream project is installed, built or executed.

Exit 0 means known development contracts passed; 1 means the replay completed
but a contract failed; 2 means an operational failure. The fresh, unlabeled
source observations are excluded from this gate. Partial outputs after a write
failure do not constitute completed evidence. CI retains both files as the
`path-development-replay` artifact.

## Separate new-source collection: no eligible path sample

The parser was frozen in commit `4b8ebc0` before the fixed three-repository
[protocol](protocol.json) was used for read-only acquisition. The
[collection](collected/collection.json) retains all outcomes:

- `astral-sh/uv`: reported license identifier fell outside the fixed allowlist;
  excluded without concluding that it lacks an open-source license.
- `pydantic/pydantic`: a regular instruction document and verified tree were
  collected, but the registered candidate grammar selected zero paths.
- `fastapi/fastapi`: neither registered root instruction filename was present.

There are **zero eligible new path cases**. The exclusions were not replaced,
and no fresh correctness or accuracy result is claimed. Collected instruction
and license bytes remain unchanged. Later parser revisions may replay this
collection as development material; the report explicitly records whether the
parser still matches the original source freeze.

## Evidence still missing

No external maintainer has been asked to validate these interpretations. This
work establishes a reproducible fix to our scanner on public inputs, with
separate removal controls. Independent reference annotation, a matched AI
comparison and sustained use by external users remain unavailable. No amount
of replaying these known cases substitutes for those forms of evidence.
