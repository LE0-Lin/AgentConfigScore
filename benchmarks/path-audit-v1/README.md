# Bounded path-reference maintainer audit

Completed on **2026-11-12 (Asia/Shanghai)** using the published **v0.26.1**
wheel. This is a provisional, AI-authored maintainer audit with retained source
facts and unfavorable results. It has no independent human labels, native Cursor
observations, AI comparison or user-adoption claim.

## Observed results

| Group | Occurrences | Flagged correctly | False positives | Missed review signals | Clean controls |
| --- | ---: | ---: | ---: | ---: | ---: |
| Unmodified public documents, selected candidates | 16 | 0 | 0 | 0 | 16 |
| Separate target-removal controls | 8 | 3 | 0 | 5 | 0 |

The natural sample contains **no reference-positive cases**. Its recall and
precision are unavailable. Four occurrences are display labels for links already
represented by their destinations. The 16 rows are correlated components from
five repositories, not 16 independent projects. Do not turn this table into a
general accuracy percentage or combine the two groups into one headline metric.

The controls remove three regular files and five directories, one target at a
time, without changing the source instruction. All three broken file links are
reported. All five literal directory references are missed under this audit's
broader review task. Current `dead-path` prose heuristics deliberately exclude
directory-style and ambiguous extensionless tokens. These misses expose that
coverage limit; they do not show that upstream projects contain broken paths.
Other findings caused by a directory removal are retained but cannot substitute
for detection at the selected literal and original source line.

The [raw report](result.json) retains every selected result, mutation and all
whole-document path findings, including unselected occurrences. A successful
replay means the experiment completed, not that every reference was detected.

## A separate post-hoc warning review

The unmodified Vitest document produced one additional, **unselected** warning
at line 201 for `docs/.vitepress/contributor-names.json`. The source explicitly
describes it as generated by `pnpm docs:contributors`.

After seeing the warning, four files were fetched at the same pinned revision.
The [retained context](posthoc-context.json) includes exact contents, SHA-256 and
Git blob IDs, verified against the already retained complete tree. `package.json`
maps that command to `scripts/update-contributors.ts`, whose lines 29–31 write
the exact named JSON file. Nothing was installed, built or executed.

The maintainer assessment is a **generated-output false positive**: absence of
the unbuilt output in Git does not establish a broken instruction. This is a
post-hoc judgement, not an independently adjudicated label. It is deliberately
outside the preselected 16-case counts. The frozen v0.26.1 report and rules are
unchanged. Any ensuing fix must use this as development evidence, not claim an
accuracy improvement on an untouched holdout.

## Exact experiment scope

This is an **isolated document path check**, not a native whole-repository scan.
The runner materializes the complete tracked name inventory as directories and
empty regular files, then places the exact selected root document at its original
path. Aliases/gitlinks are omitted and listed. Empty placeholders do not supply
source content, builds, delegated instructions, dependencies or generated output.

The installed library's discovery boundary is explicitly restricted to the
selected root document. Default path extraction, path existence rules and
finding generation are unchanged; no policy or suppression hides findings.
Only `dead-path` findings are retained. Other rule scores on these placeholders
would be meaningless and are not reported. This scope cannot establish native
instruction discovery, command correctness, security, runtime loading or complete
instruction quality.

## Reproduce

Use a Linux, case-sensitive filesystem. From a checkout, with the project source
available to the research harness and a separate frozen-package environment:

```bash
python -m venv /tmp/acs-path-audit-env
/tmp/acs-path-audit-env/bin/python -m pip install --no-deps --only-binary=:all: agent-config-score==0.26.1
PYTHONPATH=src python scripts/run_path_audit.py --python /tmp/acs-path-audit-env/bin/python --output /tmp/new-path-audit-result.json
```

The output path must be new. Replay itself uses only retained data and a local
installed library. Package installation needs network access. The
[workflow](../../.github/workflows/path-audit.yml) also verifies the wheel's
SHA-256 against the published artifact before installation. The runner checks
version and runtime source identity, launches the child with isolated Python,
and refuses incomplete/failing scans as completed evidence. It preserves the
venv invocation path rather than resolving it to a different interpreter.

Recollection is a separate, explicit network action:

```bash
PYTHONPATH=src python scripts/collect_path_audit.py --output-dir /tmp/new-path-audit-collection
```

That fetches current heads and produces a **new collection**, not a reproduction
of these pinned inputs. It never labels cases or runs the scanner, upstream
commands, model calls or maintainer messages. Keep the original collection,
observations, unfavorable results and attribution when extending this audit.
